리뷰 대상: $ARGUMENTS  (태스크 파일 또는 변경 diff)

Review 단계 — 구현자 관점 버리고 독립 검증:

1. 태스크 + 스펙의 Acceptance Criteria를 하나씩 실제로 확인. 코드/테스트로 근거 제시.
2. 보안 체크리스트 (CLAUDE.md 절대규칙):
   - [ ] 유출불가 문서가 `leakable` 컬렉션·클라우드 경로에 안 감
   - [ ] `collection_for()` 우회 없음
   - [ ] 키 평문 저장 없음 (키체인만)
3. 테스트 실제 실행 (`cargo test` / `npm test`). 통과 여부 출력 인용.
4. 범위 밖 변경·미사용 코드·계약 불일치(ipc↔commands) 점검.
5. 결과: 통과면 태스크 `done/`로 이동 지시. 불합격이면 구체적 수정 항목 나열.

칭찬 금지, 발견만. 근거 없으면 "확인 불가"로 표기.
