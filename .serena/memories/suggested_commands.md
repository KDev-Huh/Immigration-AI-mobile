# Suggested Commands

- Install deps: `npm install` for local setup; CI uses `npm ci`.
- Web UI only: `npm run dev` starts Vite on `0.0.0.0:1420`. Browser-only UI works, but IPC calls fail outside Tauri.
- Full desktop dev: `npm run tauri:dev`.
- Frontend validation: `npm run typecheck`, `npm test`, `npm run build`.
- Rust validation: from `src-tauri/`, run `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`.
- Android setup/dev/build: set `ANDROID_HOME=$HOME/Library/Android/sdk` and `NDK_HOME=$ANDROID_HOME/ndk/<version>`; then `npm run android:init`, `npm run android:dev`, `npm run android:build`.
- iOS simulator dev: prefer `npm run ios:sim` instead of raw `tauri ios dev`; script chooses/boots a simulator and fails early if port 1420 is occupied.
- iOS build without signing: `npm run ios:build:sim`.
- Android unsigned/debug artifact example from README: `npm run tauri android build -- --debug --apk --target aarch64`.
- Tauri mobile generated projects: `src-tauri/gen/` is regenerated by init commands and should not be committed.
- Memory sanity check after onboarding/updates: run `serena memories check` from repo root.
- Android GitHub Release: push a `v*` tag, e.g. `git tag v0.1.0` then `git push origin v0.1.0`; `.github/workflows/mobile-build.yml` uploads an installable APK to the Release. Manual workflow release requires `release=true` and a tag input.
- Git status: use `git status --short`; note Serena activation may create `.serena/` if onboarding was first performed.
